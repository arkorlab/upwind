This CI producer independently compiles a fixed public dynamic Pages fixture with Next.js 16.4.3 twice. It does not load the deployment SDK or apply adapter transformations. Its official NextAdapter input has only a name and a no-op `onBuildComplete`; `adapterPath` is a fixed fixture path. Next's pinned Pages template imports `getHandler` and exports `handler = getHandler(...)`. This stage collects the emitted code; it does not infer which minified declaration is that handler.

The active input is `pages/blog/[slug].js`. Its `getStaticPaths` returns the fixed `first` path with `fallback: true`; `getStaticProps` returns the requested slug, and the page renders that value. This follows the dynamic Pages shape of Next's public [native-addon fixture](https://github.com/vercel/next.js/tree/29bbeab09981148ade186e8599ecdede15abc281/test/e2e/prerender-native-module), without its native dependency. The config leaves [`bundlePagesRouterDependencies`](https://github.com/vercel/next.js/blob/29bbeab09981148ade186e8599ecdede15abc281/docs/02-pages/04-api-reference/04-config/01-next-config-js/bundlePagesRouterDependencies.mdx) unset, using the pinned Pages default. Its data cannot be combined with that previous profile to claim identity. Dynamic page inputs may change chunk grouping; they do not guarantee a particular factory, export, capture closure or genuine strict context.

Each compilation starts from a separate project, dependency store and empty home. Dependencies use a standalone integrity-pinned lock, `--frozen-lockfile` and `--ignore-scripts`. Compilation runs in the same `/work` directory, with the same constant build ID, inside an immutable Linux x64 Node image, without network or host credentials. No SDK package is installed in the fixture. Output differences fail comparison; paths, identifiers, bytes and debug data are never normalized to force agreement.

The only retained output is `UNQUALIFIED.json`: bounded original UTF-8 JavaScript from `.next/server/pages/**` and `.next/server/chunks/**`, excluding manifests, maps, inline source maps, root metadata, links and binary payloads. The collector limits entries, depth, paths, files, each file's bytes and total bytes. Compiler stdout/stderr are bounded and are not retained. Only the controlled public fixture is supported; this is not a general customer-code sanitizer.

The semantic closure is explicitly `unmapped:getHandler`. Full selected-function, capture, compact export and import closure matching remains unimplemented. An independently reviewed catalog and separate qualification are required before any runtime authority can exist. The parser checks bounded data consistency only; the empty-registry matcher never approves even a self-consistent corpus or a supplied catalog. This extractor and its empty-registry matcher do not grant production authority.

`selectPagesHandlerOrigin` in `select.mts` remains a separate marker-based data extractor with inert authored controls. The active fixture contains no such marker, so this tool does not select its framework handler. Its existing API still applies profile budgets and source hashes, requires a unique literal, nonoptional, unshadowed marker, and returns only `UNQUALIFIED` data. A direct immutable local function or `const` alias can yield original declaration/function SHA and ranges; recognized registration syntax also yields original factory/context ranges and complete typed registration IDs. A marker in another input grants no authority and does not establish that it runs.

Unknown namespace/internal import/external origins, captures and escapes retain finite unresolved reasons. Port metadata is syntax data rather than a dependency or export certificate. Reassignment, shadowed globals, global-object aliases, duplicate markers, stale source hashes and unsupported right-hand sides cannot produce a direct selection. Valid plain CJS that the optional registration parser cannot parse retains function data without factory metadata; only that parser's known `PARSE_ERROR` is sanitized, while unexpected errors propagate. Parser diagnostics never include source bodies. AST traversal is capped at 250,000 nodes per file and immutable alias resolution at 16 bindings. Only the reviewer may apply this extractor to an independently collected corpus; agents use only inert authored source controls. The extractor registry remains empty and grants no catalog, class, VM, compiler or normalization authority.
