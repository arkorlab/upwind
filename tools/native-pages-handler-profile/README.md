This CI producer independently compiles a fixed public Pages fixture with Next.js 16.4.3 twice. It does not load the deployment SDK or apply adapter transformations. Its official NextAdapter input has only a name and a no-op `onBuildComplete`; `adapterPath` is a fixed fixture path. Next's pinned Pages template imports `getHandler` and exports `handler = getHandler(...)`. This stage collects the emitted code; it does not infer which minified declaration is that handler.

The fixed fixture also imports `getHandler` from the published `next/dist/server/route-modules/pages/pages-handler.js` and assigns it to `globalThis.__upwind_public_pages_get_handler__` inside `getServerSideProps`. This server-only, fixed public input gives the reviewer a selection anchor for independent qualification. A marker in candidate code grants nothing; the reviewed registry remains empty. Missing, externalized or unclosed helper output cannot be qualified from the marker alone.

This input profile explicitly enables [`bundlePagesRouterDependencies`](https://github.com/vercel/next.js/blob/29bbeab09981148ade186e8599ecdede15abc281/docs/02-pages/04-api-reference/04-config/01-next-config-js/bundlePagesRouterDependencies.mdx). The fixed compiler [switches the Pages externalizer](https://github.com/vercel/next.js/blob/29bbeab09981148ade186e8599ecdede15abc281/crates/next-core/src/next_server/context.rs#L209-L230) from all dependencies except transpiled packages to the explicit external-package list, which does not include `next` in this profile. This suppresses that ordinary externalization path for the public deep import. It does not guarantee a shared generated factory, export or capture closure with the internal Pages template. The changed configuration SHA defines a separate fixed input profile; results remain `UNQUALIFIED` and cannot be combined with the previous profile to claim identity.

Each compilation starts from a separate project, dependency store and empty home. Dependencies use a standalone integrity-pinned lock, `--frozen-lockfile` and `--ignore-scripts`. Compilation runs in the same `/work` directory, with the same constant build ID, inside an immutable Linux x64 Node image, without network or host credentials. No SDK package is installed in the fixture. Output differences fail comparison; paths, identifiers, bytes and debug data are never normalized to force agreement.

The only retained output is `UNQUALIFIED.json`: bounded original UTF-8 JavaScript from `.next/server/pages/**` and `.next/server/chunks/**`, excluding manifests, maps, inline source maps, root metadata, links and binary payloads. The collector limits entries, depth, paths, files, each file's bytes and total bytes. Compiler stdout/stderr are bounded and are not retained. Only the controlled public fixture is supported; this is not a general customer-code sanitizer.

The semantic closure is explicitly `unmapped:getHandler`. Full selected-function, capture, compact export and import closure matching remains unimplemented. An independently reviewed catalog and separate qualification are required before any runtime authority can exist. The parser checks bounded data consistency only; the empty-registry matcher never approves even a self-consistent corpus or a supplied catalog. There is no production integration in this stage.

`selectPagesHandlerOrigin` in `select.mts` is a separate data extractor for review. It first applies the existing profile budgets and source hashes, then finds the unique literal, nonoptional, unshadowed global marker assignment. A direct immutable local function or `const` alias yields its original declaration/function SHA and ranges; recognized registration syntax also yields the original factory range, context parameter and complete typed registration IDs. The returned status is always `UNQUALIFIED`. It does not execute the fixture or establish that the marker runs.

Unknown namespace/internal import/external origins, captures and escapes retain finite unresolved reasons. Port metadata is syntax data rather than a dependency or export certificate. Reassignment, shadowed globals, global-object aliases, duplicate markers, stale source hashes and unsupported right-hand sides cannot produce a direct selection. Valid plain CJS that the optional registration parser cannot parse retains function data without factory metadata; only that parser's known `PARSE_ERROR` is sanitized, while unexpected errors propagate. Parser diagnostics never include source bodies. AST traversal is capped at 250,000 nodes per file and immutable alias resolution at 16 bindings. Only the reviewer may apply this extractor to an independently collected corpus; agents use only inert authored source controls. The production registry remains empty and no catalog, class, VM, compiler or normalization authority is granted.
